# **ESP Milestone Publication Strategy (SeedTools Enterprise)**  
*(ETH‑ready, deterministic, milestone‑based)*

## **Purpose**

This document defines the **official publication strategy** for the SeedTools Enterprise ecosystem under ESP funding.  
It ensures that all releases are:

- deterministic  
- milestone‑aligned  
- on‑chain compliant  
- reproducible  
- auditable  
- consistent with ESP expectations  

---

# **1. Publication Philosophy**

SeedTools Enterprise follows a strict rule:

> **Public releases occur *after* milestone approval and *after* receiving the on‑chain payment.**

This aligns with ESP’s funding model and protects the project from premature exposure, forks, or misinterpretation before formal acceptance.

---

# **3. Pre‑Publication Rules**

Before ESP approval:

- the repository **seedtools‑enterprise remains private**  
- no public tags  
- no public releases  
- no public documentation outside the ESP package  
- no public announcements  
- no external integrations  

This ensures:

- originality  
- novelty  
- compliance with ESP review expectations  
- protection against forks  
- protection against premature adoption  

---

# **4. Post‑Funding Publication Rules**

After ESP approves the project and releases the first milestone payment:

### **A. Repository becomes public**
- `seedtools-enterprise` is published  
- initial release tag is created  
- documentation becomes public  
- architecture becomes public  
- deterministic standards become public  

### **B. Each milestone → one deterministic release**
Every milestone must produce:

- a reproducible build  
- deterministic audit records  
- deterministic test suite  
- deterministic documentation  
- deterministic examples  
- deterministic verification paths  

### **C. Releases must be immutable**
Once a milestone release is published:

- no rewriting history  
- no force‑push  
- no tag modification  
- no retroactive changes  

ESP requires **immutable reproducibility**.
